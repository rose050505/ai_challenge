# 회귀 시험 자체를 검증한다

> **왜 이 문서가 있나.** 지금까지 두 번, 시험이 통과했는데 실제로는 깨져 있었다.
> - 스크린샷 검사가 "가로 넘침 0"이라고 했는데 서식이 잘려 있었다
>   (`document.scrollWidth` 는 **문서 전체**만 본다. 스크롤 영역 *안*의 넘침을 못 본다)
> - `tprintlong` 이 `input` 만 채워서, 표의 칸을 `textarea` 로 바꾼 뒤 **조용히 약해져** 있었다
>   (쪽 수는 5→3 으로 줄었는데 "예고=실제"는 계속 통과했다)
>
> 둘 다 "시험이 없다"가 아니라 **"시험이 있는데 아무것도 지키지 않고 있었다"** 는 문제다.
> 그래서 2026-08-31 밤에 **일부러 깨뜨려 보는 방식**(수동 뮤테이션 시험)으로 전수 점검했다.
>
> 작성 2026-08-31. 방법: 각 뮤테이션마다 소스를 고치고 → 빌드하고 → 해당 시험을 돌리고 →
> 되돌린다(`/tmp/mutate.sh`). **"고쳤다"가 아니라 "재서 확인했다"만 적는다.**

## 1. 각 시험이 실제로 무엇을 지키는가

아래 "지키는 것"은 코드를 읽고 적은 것이고, "확인 방법"은 뮤테이션으로 실제로 재본 것이다.

## 3. 시험이 없는 중요 경로 (남은 것)

보강으로 메운 것 말고, **아직 자동 검사가 없는 자리**다. 알면서 두는 것이므로 적어 둔다.

| 경로 | 왜 없나 | 대신 무엇을 하나 |
|---|---|---|
| **실제 AI 응답의 품질** | 모델 출력은 결정적이지 않다. "좋은 후보를 골랐는가"는 자동으로 못 잰다 | 서버 검산 3종(`applyGuards`·`groundedReason`·`applyInterpretGuards`)이 **형식과 근거**를 지킨다. 그 검산 자체는 `t1`·`treason` 이 지킨다 |
| **라이브 API 왕복** | 비용이 든다. `run.sh` 는 API 없이 폴백 경로만 확인한다 | `run-deployed.sh` 가 배포 뒤 **실제로 한 번 호출**한다 |
| **실제 종이** | 프린터가 필요하다 | `run-print.sh` 가 PDF 까지 간다. 그 뒤는 사람이 뽑아 본다 |
| **복수 기관 동시 행사(CaseSwitcher)의 인쇄 결과** | `phase4` 가 화면 동작은 보지만, 기관별 서식이 각각 옳게 인쇄되는지는 안 본다 | `tlong` 이 기관 4개짜리 기록으로 화면이 죽지 않는지는 본다 |
| **화면 표시 설정 키의 지속성**(`wy-font-scale`·`wy-plain`) | 여러 시험이 값을 **심기만** 하고 "다시 왔을 때 남아 있는가"는 안 본다 | 개인정보가 아니고 잃어도 손해가 없다. 우선순위를 낮게 뒀다 |
| **다른 브라우저**(Firefox·Safari 실기) | 이 기계에 없다 | `safari.mjs` 가 `@page` 지원 여부를 **기능 감지**로 판별하고, 지원하지 않으면 화면이 "쪽 수가 다를 수 있다"고 말한다 |

## 4. 이 점검에서 배운 것

**세 번 다 원인이 같았다.**

1. 스크린샷 검사 — `document.scrollWidth` 라는 **바깥의 고정점이 아닌 것**을 봤다
2. `tprintlong` — `input` 만 채워서, 채우는 대상이 바뀌자 **검사가 스스로 약해졌다**
3. 이번 9건 — `tlaw`·`tmatrix`·`tj` 가 **상수끼리, 판정끼리만** 비교했다

> **규칙으로 적어 둔다.**
> 시험은 **바깥의 고정점**을 하나 이상 가져야 한다.
> - 법조문·판본·서식 문구 → **리터럴**로 적는다 (원문에서 옮긴 값)
> - 판정 → **정답 오라클**을 따로 둔다 (일관성 검사는 오라클이 아니다)
> - 조판 치수 → **다른 파일의 값과 대조**한다 (CSS ↔ JS)
> - 화면 문구 → **그 문구가 실제로 쓰이는 화면**에서 확인한다 (상수를 import 해서 비교하면 동어반복이다)
> - 값을 채우는 검사 → 채우는 **대상의 개수를 함께 확인**한다 (16칸이면 16칸이라고 적는다)
