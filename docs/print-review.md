# 인쇄물 검수 — 완성된 종이가 실제로 쓸 만한 문서인가

> 지금까지의 인쇄 검증은 **"쪽 수가 맞나 / 글자가 빠지나"** 였다.
> 이 문서는 다른 것을 본다 — **금융회사 담당자가 이 종이를 받았을 때,
> 그리고 사용자가 이 종이에 볼펜으로 쓸 때 어떤가.**
>
> 작성 2026-08-31. 방법: `tests/out/` 의 실제 PDF 를 이미지로 뽑아 보고,
> 글자 위치는 `pdftotext -bbox` 로 **재서** 확인했다. 추정한 값은 적지 않는다.
>
> ★ **`.print-sheet` 안쪽은 동결이다.** 쪽 수 예고가 그 높이로 계산되므로,
>   안쪽을 건드리면 `run-print.sh` 10조합을 전부 다시 돌려야 한다.
>   그래서 아래 항목은 **[고쳤다] / [보고만]** 으로 나눠 적는다.

---

## 1. 담당자가 받았을 때

### 무엇을 먼저 보게 되나 — 확인함

제목(중앙·굵게) → `1. 제도 안내`(고정 안내문 6줄) → `2. 요청 내용` 순서다.
**요청 내용에 닿기까지 고정 안내문 6줄을 지나야 한다.** 이건 고시 서식의 구조 그대로이므로
바꾸지 않는다. 바꾸면 그 순간 "고시 서식"이 아니게 된다.

### 낱장이 흩어져도 순서를 알 수 있는가 — **된다**

- 모든 쪽 하단에 `- N / M -` 이 찍힌다. **총 장수를 알 수 있다.**
  (Chrome 은 `counter(pages)` 를 지원하지 않아, 화면 밖에서 높이를 재어 우리가 직접 나눈다)
- 2쪽부터는 상단에 **반복 머리**가 붙는다 — 왼쪽에 서식 이름, 오른쪽에 신청인 이름.
- 다만 **1쪽에는 반복 머리가 없다**(제목이 그 자리다). 1쪽만 떨어지면 신청인은
  섹션 2 리드의 밑줄 자리로만 알 수 있다. 서식 1은 인적사항 표가 있어 해당 없음.
  → 고칠 수 있지만 `.print-sheet` 안쪽이다. **[보고만]**

### 빈칸이 어디인지 한눈에 보이는가 — **보인다**

표의 격자가 그대로 인쇄되어 손으로 채울 자리가 명확하다.
체크 항목(서식 1)은 켠 것만 `✓` 로 나가고 끈 것은 빈 네모로 나간다.
(`tprintlong` 이 "켠 4개가 ✓ 로 나온다 / 전부 끄면 ✓ 가 없다"를 확인한다)

## 2. 손으로 채운다고 가정했을 때 — 실측

| 자리 | 실측값 | 판단 |
|---|---|---|
| 표의 빈 행 높이 | `--sheet-row-height: 20pt` = **7.06mm** (큰 글씨 8.82mm) | ⚠ **빠듯하다.** 볼펜 글씨는 4~6mm 이고 위아래 여백을 더하면 8~10mm 가 편하다 |
| 서명 자리 (`신청인 :` 끝 ~ `(서명 / 인)` 시작) | x 486.2pt → 512.6pt = **26.4pt = 9.3mm** | ⚠ **좁다.** 한국 인장은 보통 지름 15mm 다. 9.3mm 에는 안 들어간다 |
| 날짜 자리 (`20` 뒤 ~ 오른쪽 끝) | 약 **42pt = 14.8mm** 에 `년/월/일` 세 칸 | ⚠ 좁다. 두 자리 숫자 두 개를 쓰기에 빠듯하다 |
| 주민등록번호 칸 (서식 1) | 표의 한 행. 값은 **공란**이고 옆에 안내가 인쇄된다 | 아래 §3 참조 |
| 증빙자료 목록 자리 | **없다.** `※ 붙 임 : 증빙자료` 라벨만 있고 목록을 쓸 빈 줄이 없다 | 고시 서식이 그렇다. §3 참조 |

세 가지(행 높이 · 서명 · 날짜) **모두 `.print-sheet` 안쪽 치수**다.
고치면 블록 높이가 바뀌어 쪽 수 예고가 어긋난다. **[보고만]**

> 고친다면 어디를 고쳐야 하는지만 적어 둔다 (대회 후):
> - 행 높이: `src/index.css` 의 `--sheet-row-height: 20pt` → 24pt 정도
> - 서명·날짜: 서식 2의 서명 블록에 가로 여백을 넣는다
> - **고친 뒤에는 반드시 `tests/run-print.sh` 전부(쪽수 10조합 + 값 잘림 42칸)**

## 3. 두 가지 실제 문제

### 3-1. 서식 1의 주민등록번호 안내가 **종이에 그대로 찍힌다** — [보고만]

인쇄물에 이렇게 나온다:

> 주민등록번호 | `-` (출력 후 직접 기재하세요 — 이 서비스는 주민등록번호를 입력받지 않습니다.)

앞부분("출력 후 직접 기재하세요")은 사용자에게 필요하다. 그런데 뒷부분
("이 서비스는 주민등록번호를 입력받지 않습니다")은 **접수 담당자가 읽게 되는 문장**이고,
담당자에게 "이 서비스"가 무엇인지 알 길이 없다. 고시 서식 원본에 없는 문구이기도 하다.

- **왜 안 고쳤나**: `.print-sheet` 안쪽이다. 한 줄이 두 줄이 되거나 그 반대가 되면
  서식 1의 높이가 바뀌고, `SheetHeightProbe` 가 재는 값도 바뀐다.
  서식 1은 지금 1쪽이라 실제로 쪽 수가 바뀔 가능성은 낮지만, **낮다는 것은 재보지 않았다는 뜻**이다.
- **고친다면**: 인쇄용 문구를 `(출력 후 직접 기재)` 로 줄이고, 긴 설명은 화면에만 둔다.
- **고쳤다 (2026-08-31, 사용자 승인).** `FORM1_APPLICANT_FIELDS.residentNumber.note` 를
  `'출력 후 직접 기재'` 로 바꿨다. 화면의 빈 칸 점검은 그대로 긴 설명을 유지한다.
  쪽 수 예고=실제 10/10 재확인.

### 3-2. 증빙자료 목록을 적을 자리가 서식에 없다 — [고쳤다, 화면에서]

`※ 붙 임 : 증빙자료` 라벨만 있고 무엇을 붙였는지 적을 칸이 없다.
**이건 고시 서식이 그런 것이므로 서식을 고치지 않는다.**
대신 인쇄 전 점검 목록의 해당 항목에 한 줄을 더했다 —
서식에 목록 칸이 없으니 별지에 적어 함께 보내면 접수·대조가 쉽다는 안내.
**법이 요구하는 것이 아니라 실무상 권하는 것임을 문장에서 밝힌다.**

## 4. 열 너비 — 확인한 것과 확인하지 못한 것

섹션 2의 `현행 정보` 와 `정정 또는 삭제 내용` 은 **같은 너비**다(각각 화면 폭의 약 38%).
실제로는 정정 내용이 더 길어지기 쉽다("이 값이 틀렸고, 실제로는 이렇고, 근거는 이것이다").

- **확인하지 못한 것**: 고시 별지 원본에서 이 두 열의 너비가 같은지.
  원본(HWP 첨부)을 받지 못했다(`docs/facts.md` §7-1).
  원본이 같은 너비라면 지금이 맞고, 다르다면 지금이 틀렸다. **알 수 없으므로 바꾸지 않는다.**
- 값이 잘리지는 않는다 — 열이 좁으면 줄바꿈되고, 42칸 전수 검사가 그것을 확인한다.

섹션 3의 `정보명` 은 `세부 내용` 보다 좁다. 이쪽은 내용 길이와 맞는다.
