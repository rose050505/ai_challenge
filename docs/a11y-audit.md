# 접근성 실검증 — 2026-08-31 (Phase 4)

전 화면(8개)을 스크린리더가 읽는 방식으로 훑었다. 검사 자체를 회귀 시험(`tests/ta11y.mjs`, 76항목)으로 남겼다.
외부 도구(axe 등)는 넣지 않았다 — 새 의존성을 늘리지 않기로 했고, 아래 항목은 DOM 만으로 판정된다.

## 고친 것

### ① `aria-controls` 가 없는 id 를 가리키고 있었다 — 6화면 전부

접기/펼치기와 용어 풀이는 **닫혀 있을 때 패널을 DOM 에서 뺀다**(인쇄 때 `beforeprint` 로 되살린다).
그런데 `aria-controls` 는 닫힌 상태에서도 붙어 있어, 보조기기가 **존재하지 않는 id** 를 가리켰다.

고침: 패널이 실제로 있을 때만 `aria-controls` 를 준다. 접힘/펼침은 `aria-expanded` 가 이미 알린다.
(`Disclosure` · `Term` · `NoReply` · `EmailDraft`. `/diagnose` 의 샘플 목록은 `hidden` 속성만 쓰고
DOM 에는 남아 있으므로 그대로 둔다.)

### ② 인쇄 서식 표의 `th` 에 `scope` 가 없었다

서식 1의 인적사항 표, 서식 2의 정정표·유리한 정보 표. 열 머리인지 행 머리인지가 없으면
스크린리더가 각 칸을 읽을 때 어느 항목인지 말해 주지 못한다.

고침: 세로 머리에 `scope="row"`, 표 위 머리에 `scope="col"`. **보이는 모양과 인쇄물은 그대로다.**
(`/response` 와 랜딩의 표에는 이미 있었다.)

## 남은 것 (고치지 않음)

### 모달이 떠 있는 동안 배경에 `aria-hidden`/`inert` 를 걸지 않는다

`aria-modal="true"` 가 있으면 요즘 스크린리더는 대화상자 밖을 읽지 않는다.
배경에 `inert` 를 거는 쪽이 더 확실하지만, 잘못 걸면 **모달이 닫힌 뒤 화면 전체가 조작 불가**가 된다.
심사 기간에 그 사고가 나는 쪽이 훨씬 나쁘다. 포커스 가둠은 이미 실측으로 확인했다.

### 모달을 Esc 로 닫으면 포커스가 화면 맨 위로 간다

이 모달은 첫 방문에 **저절로 열린다.** 연 사람이 없으니 돌려줄 자리도 없다.
맨 위(본문으로 건너뛰기)로 가는 것이 어색하지 않다고 보고 그대로 둔다.

### 랜딩에서 `<details>` 를 한 곳에 쓴다

나머지는 전부 `button` + `aria-expanded` 로 통일돼 있는데 랜딩의 "기록은 어디에 남나요"만
`<details>` 다. 둘 다 접근 가능하지만 여는 방법이 두 가지가 된다.
동작에는 문제가 없어 지금 바꾸지 않는다. 바꾸려면 인쇄 시 펼치는 처리까지 함께 옮겨야 한다.
