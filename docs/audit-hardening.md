## [1] CSP + Origin 가드

### CSP 에서 막힌 것 · 열어 준 지시어

**막힌 것: 없다. 열어 준 예외: 없다.**

넣은 값은 요청한 그대로다 (`vercel.json`):

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
img-src 'self' data:; connect-src 'self'; frame-ancestors 'none';
base-uri 'self'; form-action 'self'
```

`vite preview` 에는 배포 헤더가 실리지 않으므로, **`vercel.json` 의 헤더를 그대로 실어
`dist/` 를 서빙하는 서버**(`tests/csp-server.mjs`)를 만들고 그 위에서 전 경로를 걸었다
(`tests/tcsp.mjs`, 24건).

| 걱정했던 곳 | 결과 |
|---|---|
| 내보내기 `blob:` URL 다운로드 | 통과. `a[download]` 는 CSP 지시어의 대상이 아니다 |
| 이메일 초안 `mailto:` | 통과. 링크 네비게이션이라 `form-action` 에 걸리지 않는다 |
| 인라인 `<style>` | `style-src 'unsafe-inline'` 로 이미 허용 |
| Tailwind·React 번들 | 전부 자기 호스트라 `'self'` 로 충분 |
| `/api` 호출 | same-origin 이라 `connect-src 'self'` 통과. 이 서버에 `/api` 가 없어 404 → 화면은 폴백 목록으로 정상 진행 |
| 웹폰트 | 애초에 0개. `document.fonts.size === 0` 을 시험으로 고정했다 |

**탐지기 자체를 먼저 의심했다.** 위반 0건은 탐지기가 죽어 있어도 나오는 값이다.
일부러 외부 fetch·외부 스크립트·외부 이미지를 넣어 보니 `connect-src`·`script-src-elem`·
`img-src` 3종이 **두 경로 모두**(`securitypolicyviolation` 이벤트 + CDP `Log.entryAdded`)에서
잡혔다. 그 뒤에야 0건을 신뢰했다.

### Origin 가드 (`api/_origin.js`)

- 허용: `362.parkmiyeong.com` · `autoevalrights.vercel.app` ·
  `autoevalrights-*.vercel.app`(프로젝트 프리뷰) · `localhost`/`127.0.0.1`.
- **`*.vercel.app` 전체를 열지 않았다.** 열면 Vercel 에 배포한 아무 사이트나 통과한다.
- **Origin 이 없는 요청은 막지 않는다.** same-origin 에 Origin 을 싣지 않는 환경이 있고,
  사용자를 잘못 막는 비용이 무임승차를 막는 이득보다 크다.
- **키 확인보다 먼저 검사한다** → 403 에 API 비용이 들지 않는다.
- 한계: curl 은 Origin 을 위조할 수 있다. 이것은 차단이 아니라 완화다.

개발 서버로 실제 확인:

| 요청 | 결과 |
|---|---|
| `Origin: https://example.com` | **403** `forbidden_origin` (Claude 호출 없음) |
| `Origin: http://localhost:5173` | 통과 → 본문 검증 400 |
| Origin 없음 | 통과 → 본문 검증 400 |

`tests/run-deployed.sh` 가 CSP 헤더 존재와 낯선 Origin 403 을 함께 확인한다.

## [3] 회신 해석의 근거 인용

### 무엇이 바뀌었나

- `/api/interpret` 이 `coveredEvidence` 를 받는다 — 받았다고 판정한 유형마다
  "그렇게 본 근거가 된 회신문의 한 문장".
- `verifiedQuote()` 가 그 문장이 **회신 원문에 그대로 있는지** 대조하고, 없으면 버린다
  (`/strategy` 의 `groundedReason` 과 같은 원리).
- **지금까지 대조 없이 화면에 올라가던 `refusalReasonText`·`provisoText` 도 이제 대조한다.**
  이 둘도 "회신에 이렇게 적혀 있다"는 주장인데 검산이 없었다.
- 화면: "받음" 줄 아래에 `회신문의 이 문장 때문입니다` + 인용.
  **"못 받음" 줄에는 인용이 없다** — 없는 문장은 인용할 수 없다.

### 판정은 한 줄도 바뀌지 않았다

검산을 **논리 검증 뒤에** 둔 것이 핵심이다. 먼저 하면 인용이 사라지면서 판정이 따라 바뀐다
(거절→법정 제외 이동이 `refusalReasonText` 의 존재를 보고 일어나기 때문).
그래서 "제외로 판정했으나 인용은 없음"이 나올 수 있다 — 지어낸 문장을 회신에 있는 척
보여주는 것보다 낫다. `tests/tquote.mjs` `[B4]` 가 이 순서를 고정한다.

### 라이브 호출 결과 (실제 API 1회, 4.0초, HTTP 200)

캐시에 없는 회신문을 새로 만들어 넣었다 (`tests/live-quote.mjs`).

| | 값 |
|---|---|
| 판정 | covered `result`,`baseInfo` / missing `criteria` / `excludedByProviso: true` |
| 모델이 낸 인용 | 3개 (`result`, `baseInfo`, `provisoText`) |
| **검산에 걸려 버려진 인용** | **0개** — 셋 다 회신 원문에 그대로 있었다 |
| 지어낸 인용 2개를 일부러 주입 | **2개 모두 버려짐** (0개 남음) |

곁가지 관찰: `baseInfo` 의 인용으로 모델이 `"재직기간: 5개월"` 이라는 **목록 한 줄**을 골랐다.
문장이 아니라 항목이다. 원문에 그대로 있으므로 거짓은 아니지만, 읽기로는 앞의 안내 문장이

"틀리지 않은 인용"을 지키는 쪽이 낫다고 봤다.

### 샘플은 결정론적이다

샘플 2종은 캐시라 서버를 타지 않는다. 그래서 인용을 캐시에 미리 넣고,
**그 문장이 샘플 본문에 그대로 있는지**를 `tquote.mjs` 가 시험한다.
심사위원이 보는 경로에는 모델이 개입하지 않는다.

새로고침 뒤에도 인용이 남는지 확인했다 — 저장소 정규화(`normalizeInterpretation`)가
모르는 필드를 버리므로 `normalizeEvidence` 를 함께 넣었다.
불러온 파일은 원문이 없어 재대조할 수 없다(원문을 저장하지 않는 설계다).
