## [1] 완전한 첫 방문 — 캐시도 기록도 없는 상태

캐시·쿠키·localStorage 를 모두 비우고, DevTools 표준 회선값으로 잰다.

| 화면 | 회선 | TTFB | FCP | DCL | 카드 3장이 다 그려짐 | 레이아웃 이동 |

| 375px | 빠른 3G | 19ms | 1,016ms | 958ms | 1,006ms | 0 |
| 375px | 느린 3G | 18ms | 3,332ms | 3,287ms | 3,383ms | 0 |

  높이 4,955~6,667px, 글자 3,271~3,346자로 **다 그려져 있다.** 빈 화면 위에 모달만
  뜨는 일은 없고, 랜딩이 먼저 보였다가 모달이 덮치는 것도 아니다(같은 그림에 함께 나온다).

### ★ 고쳤다 — 1280px 에서 투어 패널이 592px 뛰었다

첫 그림에서 패널이 화면 위(y=16)에 나왔다가 100ms 뒤 아래(y=608)로 내려왔다.

정거장이 열리면 대상을 화면 위쪽으로 부드럽게 스크롤하는데, 첫 그림 시점의 대상은

그 값은 스크롤 중에 변하지 않으므로 패널은 처음부터 제자리에 그려진다.
375px 은 원래 하단 시트라 영향이 없었다(변경 전에도 CLS 0).

→ `tests/tcold.mjs` 로 고정했다. 되돌려 보니 2건이 실패했다(레이아웃 이동 0.233, 자리 `[16,608]`).

## [2] ★ 5분 체험 재측정 — 이 감사의 핵심

원래 진단(`docs/self-review.md`): **"5분 체험으로는 서식 생성기로 읽힌다."**

### 재는 방식

시간을 지어내지 않는다. 경로를 실제로 걸으며 (가) 어느 화면에 닿는가 (나) 그 화면에
차별점이 **보이는가** (다) 클릭 몇 번·새로 읽을 글자 몇 자인가를 재고,
**[클릭 2초 + 훑어읽기 900자/분]** 이라는 밝힌 환산식으로 시간을 낸다.
같은 문단은 다시 세지 않는다. 투어 중에는 모달 글과 **그 정거장이 비추는 부분**을 함께 센다.

### 결과

| 경로 | 5분 시점에 도달한 곳 | 5분 안에 전달된 차별점 |
|---|---|---|
| **투어를 본 사람** (375·1280) | **끝까지 (전 과정 4분 1초)** | **4/5** — 근거 조문 · 거절 vs 법정 제외 · 확인 못 한 것을 비움 · 서버 검산 |
| 투어를 건너뛴 사람 (375·1280) | 랜딩 + 진단 입력까지 (전 과정 11분 30초) | 3/5 — 전 주기 · 근거 조문 · 서버 검산 |

투어 경로 상세 (375px):

| | 화면 | 새 글 | 그 자리에서 전달되는 것 |
|---|---|---|---|
| 1 | 랜딩 + 투어 소개 | 615자 | — |
| 2 | 정거장 1 `/diagnose?sample=returner` | 308자 | 근거 조문 |
| 3 | 정거장 2 `/response?sample=partial&run=1` | 1,409자 | 근거 조문 · **거절 vs 법정 제외** · 확인 못 한 것을 비움 |
| 4 | 정거장 3 `/document?form=correctionRequest` | 212자 | — |
| 5 | 마무리 | 114자 | — |
| 6 | 마무리 링크 → `/strategy` | 810자 | 근거 조문 · **서버 검산** |

### 판정 — 원래 진단은 아직 유효한가

**기본 경로에서는 더 이상 유효하지 않다.** 처음 온 사람에게는 투어가 저절로 열리고,
그 경로는 4분 1초에 끝나며 다섯 중 넷을 전달한다. 특히 정거장 2 는
"이것은 요구를 거절한 것이 아닙니다. 요구에는 응하면서, 법이 제외를 허용한 범위만큼
설명의 폭을 줄인 것입니다"를 화면에 그대로 띄운다 — 서식 생성기가 할 수 있는 말이 아니다.

**투어를 건너뛴 사람에게는 절반쯤 유효하다.** 5분이 랜딩(3,148자)과 진단 입력에서 다 간다.
회신 해석에도 서식에도 닿지 못한다. 다만 이 숫자는 **랜딩을 처음부터 끝까지 읽는다는
가정의 최악값**이다. 랜딩은 훑어보라고 만든 화면이라(진입 카드), 스크롤로 지나가는
사람은 1분 안에 `/diagnose` 에 닿는다. 그 경우의 5분은 위 표의 아래 칸보다 낫다.
**그 차이를 우리는 재지 않았다** — 훑는 속도를 정할 근거가 없어서다.

### 아부하지 않고 말하면

- 5분 안에 **한 번도 전달되지 않는 것은 "전 주기"** 하나다(투어 경로).
  투어의 순서 자체가 전 주기이지만, 그것을 **그림으로 보여주는 자리는 랜딩 하나**이고
  투어를 본 사람은 랜딩을 스크롤하지 않는다.
  → 고치지 않았다. 랜딩에 그림을 하나 더 넣거나 정거장을 하나 더 만드는 것은
  둘 다 앞선 결정(첫 화면을 훑기 쉽게 · 정거장 셋)을 뒤집는 일이다.
- **투어를 끝까지 본 사람의 5분은 "다 봤다"가 아니라 "다 보고도 1분이 남는다"이다.**
  남은 1분에 무엇을 하게 할지는 정하지 않았다. 마무리 화면이 `/strategy` 로만 길을 연다.

### ★ 고친 것 두 가지 (둘 다 [2] 때문에)

1. **랜딩에 "이 서비스에서 AI가 하는 일" 두 줄을 넣었다.**
   그 전에는 랜딩이 AI 를 두 번 말하는데 둘 다 우리 이야기가 아니었다 —
   히어로의 "AI가 내린 심사 결과"(금융회사의 AI)와 개인정보 고지 한 줄.
   *이 대회의 심사위원이 가장 먼저 물을 것에 첫 화면이 답하지 않고 있었다.*
   문구는 `ArchitectureDiagram` 의 캡션과 같은 사실만 쓴다. 그림은 다시 그리지 않고
   그림이 있는 자리(`/strategy`)로 링크를 건다.
2. **투어 마무리에 `/strategy` 로 가는 길을 하나 열었다** (`TOUR_OUTRO.link`).
   정거장을 늘리지 않는다. 누를지는 사용자가 정한다.
   이 하나로 투어 경로의 전달이 3/5 → **4/5** 가 됐다.

## [4] API 가 죽은 상태로 전 경로

CDP `Fetch` 로 `/api/*` 를 가로채 상태를 강제했다. **실제 API 는 한 번도 부르지 않았다(비용 0).**
각 경우마다 (가) 사용자가 직접 쓴 서술로 `/strategy` (나) 붙여넣은 회신으로 `/response`
(다) 샘플 경로 — 셋을 끝까지 걸었다. **65개 확인 전부 통과.**

| 강제한 상태 | 화면이 하는 말 | 사용자가 막히는가 |
|---|---|---|
| 503 (키 없음, JSON) | "AI 연결이 일시적으로 어려워 기본 목록을 보여드립니다" | 아니다 — 5개 항목 · 서식까지 완주 |
| 502 (HTML 오류 페이지) | "기본 목록을 보여드립니다" / "직접 분류 모드로 전환했습니다" | 아니다 |
| 504 (빈 본문) | 같음 | 아니다 |
| 429 (한도 초과) | "요청이 많아 기본 목록을 보여드립니다" | 아니다 |
| 연결 실패 | "AI 연결이 일시적으로 어려워…" | 아니다 |
| **무응답** | 8초에 "조금 더 걸리고 있습니다. 25초 안에 응답이 없으면 기본 목록으로 넘어가니 새로고침하지 말고 기다려 주세요" → 25초에 "응답이 지연되어…" | 아니다. 단추가 "만드는 중"에 갇히지 않는다 |

- **샘플 경로는 어느 경우에도 API 를 0회 부른다.** 심사위원이 샘플로 체험하는 한
  API 상태와 무관하게 선정이유까지 그대로 나온다.
- 어떤 경우에도 화면이 "오류"라는 말로 끝나지 않는다.

### ★ 이 상태로 보면 어떻게 읽히는가

**"AI 없이도 되는 서비스"로 읽힌다.** 근거는 폴백 문구가 아니라 **그 위에 남아 있는 그림**이다.
API 가 죽어도 `/strategy` 의 "이 화면에서 AI는 어디까지 하나요" 도식과
"법정 사실은 결정론적으로, 사용자 맥락 해석만 LLM으로 처리합니다"는 그대로 보인다.
그 아래에 5개 항목이 각각 `법 제2조 제1호의5` 근거를 달고 정상적으로 나온다.
읽는 순서가 [AI는 맥락만 옮긴다] → [이번엔 AI가 안 됐다] → [그래도 목록은 있다] 라서,
"핵심이 죽었다"가 아니라 "부가 기능이 쉬었다"로 읽힌다.

부족한 점 하나: 폴백 문구가 **이번 화면**에 대해서만 말한다("이번에는 상황을 읽지 못해").
"나머지 기능은 그대로입니다"라고는 말하지 않는다. 도식이 대신하고 있으나 말로는 없다.
→ 고치지 않았다. 문구를 늘리면 실패를 더 크게 보이게 만든다.

## [5] 동시 접속

실제로 부하를 걸지 않았다. 설정과 코드로 판단한다.

### 재 본 것

`jd5-requests.mjs` — 여섯 화면을 열고 접힌 것까지 전부 펼쳤을 때:

| 화면 | 요청 수 | 바깥(다른 출처) | `/api/` |
|---|---|---|---|
| `/` · `/diagnose` · `/strategy` · `/document` · `/next` · `/response` | **각 3건** | **0건** | **0건** |

- **화면을 여는 것만으로는 서버리스 함수가 한 번도 불리지 않는다.** 글을 붙여넣기만 해도 0건.
  `[회신 해석하기]`를 눌러야 정확히 1건.
- 따라서 심사위원 여럿이 동시에 여는 것은 **CDN 부하**이지 함수 부하가 아니다.
  배포본 응답에 `x-vercel-cache: HIT`, `x-vercel-id: icn1`(서울 엣지)이 찍힌다.

### 설정으로 아는 것

| 값 | 어디 | 뜻 |
|---|---|---|
| `maxDuration: 30` | `vercel.json` | 함수 하나가 30초를 넘기지 않는다 |
| `timeout: 22_000`, `maxRetries: 1` | `api/analyze.js` · `api/interpret.js` | **한 번 누름 = 상류 호출 최대 2회.** 폭주로 증폭되지 않는다 |
| `CLIENT_TIMEOUT_MS = 25_000` | `analyze-client.js` · `interpret-client.js` | 22 < 25 < 30 — 서버가 먼저 답하고, 클라이언트가 그 다음, 플랫폼이 마지막 |
| `cache-control: public, max-age=0, must-revalidate` | 배포본 응답(정적 파일 포함) | 심사위원 브라우저가 **매번 재검증**한다 → 옛 판을 보게 될 위험이 낮다 |

### 판단할 수 없는 것 (사용자 확인 필요)

- **Vercel 플랜의 동시 실행·호출 한도** — 저장소에서 알 수 없다.
- **Anthropic 키의 분당 요청 한도** — 알 수 없다.

다만 둘 중 무엇이 걸려도 결과는 429/503 이고, [4]에서 그 상태를 끝까지 걸어 봤다.
**한도에 걸려도 화면은 완주한다.**

## [8] 그 밖에 — 우리가 확인한 적 없던 것

### [8-1] ★ 배포본 CSS 가 로컬 빌드와 다르다 — 원인을 찾아 고쳤다

같은 커밋인데 **배포본 CSS 가 로컬보다 1,786바이트 컸다.** JS 는 바이트까지 같았다.
늘어난 것은 지금 아무도 쓰지 않는 유틸리티 넷 — `.visible` `.italic` `.blur` `.transition!`
와 그에 딸린 `@property --tw-*` 13개.

처음에는 원인을 못 찾았다(`.git` 유무·`.gitignore` 를 바꿔도 로컬에서 재현되지 않았다).
**이 감사를 기록하다가 원인을 만났다** — 이 문서(`docs/audit-judgeday.md`)와 감사
스크립트를 저장소에 넣고 빌드했더니 CSS 가 **36.1KB → 39.3KB 로 늘었다.**

> Tailwind v4 의 기본 소스 탐지는 **저장소 전체를 훑는다.** 그래서 `docs/*.md` 나
> `tests/*.mjs` 에 클래스 이름을 **적기만 해도** 그 규칙이 배포 CSS 에 들어간다.
> `src/index.css` 안의 `word-break: break-all` 같은 **평범한 CSS 선언**까지 토큰으로
> 읽혀 `.break-all` 유틸리티를 만들어 냈다.
> 배포본의 유틸리티 넷도 같은 경로다 — 빌드 환경에 우리 쪽에 없는 파일이 있었던 것이다.

→ **훑을 곳을 소스로 못 박았다** (`src/index.css`):

```css
@import "tailwindcss" source(none);
@source "../index.html";
@source "./**/*.{js,jsx}";
```

- 어디서 빌드하든 같은 CSS 가 나온다. **재현 가능해졌다.**
- 결과: 35.4KB (감사 전 36.1KB 보다 **0.7KB 작다**).
  빠진 7개 — `.-mx-4` `.break-all` `.break-words` `.flow-root` `.ring` `.ring!` `.rounded` —
  는 `src/**/*.jsx` 어디에서도 쓰지 않는다(전수 확인). 쓰는 `.rounded-md` `.ring-2`
  `.ring-ink-200` 은 그대로 있고, 규칙 내용이 감사 전과 **글자까지 같다.**
- 새로 생긴 규칙 0개. 즉 **없던 것이 생기지도, 쓰던 것이 사라지지도 않았다.**
- → 그래도 `tests/depcss.mjs` 를 남긴다. **JS 가 바이트까지 같을 때만** CSS 규칙 집합을
  비교한다(같으면 소스가 같다는 뜻). 배포 환경이 또 다른 것을 훑는 날 여기서 드러난다.
