# 「자동화평가 결과에 대한 설명요구서」 서식 명세

출처: 금융위원회 고시 서식 (제40조의5제1항 관련) — BC카드 공개본 기준
근거: 신용정보법 시행령 제31조의2 제6항 ("금융위원회가 정하여 고시하는 서식")

> 이 문서는 `/document` 화면이 재현해야 할 **레이아웃과 필드의 정본**이다.
> 문구를 임의로 다듬지 말 것. 고시 서식이라는 점이 이 서비스의 신뢰 근거다.

---

## 서식 구조

### [제목]
```
자동화평가 결과에 대한 설명요구서
(제40조의5제1항 관련)
```

### [섹션 1] 신용평가주체의 대응권 개요

고정 안내문. **사용자 입력 없음. 문구 수정 금지.**

내용 요지 (원문 그대로 렌더링할 것):
- 개인인 신용정보주체는 신용정보법 제36조의2 제1항·제2항 및 하위법령에 따라
  개인신용평가회사 및 대통령령으로 정하는 신용정보제공·이용자에 대하여
  자동화평가 실시 여부, 그 결과·주요기준·기초정보의 개요 등의 설명을 요구할 수 있음
- 또한 유리하다고 판단되는 정보의 제출, 기초정보의 정정·삭제 및
  자동화평가 결과의 재산출을 요구할 수 있음
- 다만 아래의 경우 금융회사가 요청을 거부할 수 있음
  - 다른 법령 등에 특별한 규정이 있는 경우
  - 요구에 따르면 금융거래 등 상거래관계의 설정 및 유지 등이 곤란한 경우
  - 정정·삭제 요청 내용이 사실과 다른 경우
  - 동일한 금융거래에 대해 3회 이상 반복적으로 권리를 행사하는 경우

> ★ **불일치 (2026-08-23 확정 처리 방침)**
> 위 네 번째 항목에는 시행령 제31조의2 제5항 제2호의 요건인 **"정당한 사유 없이"가 빠져 있다.**
>
> - 서식 렌더링 영역: **원문 그대로 둔다. 문구 수정 금지.**
> - 서식 **밖** 안내 영역에서만 시행령 원문으로 보정한다.
>   > "고시 서식의 안내문에는 생략되어 있으나, 시행령 제31조의2 제5항 제2호는
>   > '정당한 사유 없이' 3회 이상 반복한 경우로 한정하고 있습니다."
> - 이 불일치는 **의도적으로 화면에 드러낸다. 삭제하지 말 것.**
> - 상수: `FORM_SECTION1_REFUSAL_NOTICE` / `FORM_SECTION1_DISCREPANCY` (`src/data/law.js`)

### [섹션 2] 요청 내용

리드 문장 (밑줄 부분이 사용자 입력):
```
______(성명)______ 은(는) 귀 사의 상기 설명 내용을 듣고 이해하였으며,
이에 따라 아래 내용에 대해 설명을 요구합니다.
```

선택 항목 (다중 선택 가능):

| ID | 라벨 | 근거 조문 | 비고 |
|---|---|---|---|
| `result` | ① 자동화평가의 결과 | 법 §36-2①2가 | 부기란 있음 (아래 참조) |
| `criteria` | ② 자동화평가의 주요 기준 | 법 §36-2①2나 | |
| `baseInfo` | ③ 자동화평가에 이용된 기초정보의 개요 | 법 §36-2①2다 | |

①의 부기란:
```
(신청인 희망 신용평가 결과 : 금융회사 안내를 받아 기재)
```
→ 사용자가 작성 시점에 모를 수 있는 항목. **필수 입력으로 만들지 말 것.**
   "모르면 비워두고 창구 안내를 받아 기재" 안내 문구를 UI에 붙인다.

### [섹션 3] 신청자 인적사항

| 필드 | 서식상 존재 | 우리 서비스 처리 |
|---|---|---|
| 성명 | O | 입력받음 (**서버로 보내지 않는다.** 이어서 쓸 수 있게 이 브라우저의 `localStorage` 에는 저장된다) |
| 주민등록번호 | O (`___-___` 형태) | **입력받지 않음. PDF에서 공란 출력 + 직접 기재 안내** |
| 휴대폰 | O | 입력받음 (선택) |
| 이메일 | O | 입력받음 (선택) |

> 주민등록번호 미수집은 이 프로젝트의 핵심 설계 결정이다.
> 기능명세서 4번(개인정보·민감정보 처리 여부) 항목에 그대로 서술한다.

### [섹션 4] 개인신용정보 제공 동의

고정 문구 + 체크박스:
```
※ 이와 관련, 본인은 귀 사가 신용정보집중기관 또는 개인신용평가회사,
   개인사업자신용평가회사 또는 기업신용조회회사 등으로부터
   본인의 개인신용정보를 제공받는 것에 동의합니다.
                                      (동의 □ / 비동의 □)
```

→ 사용자가 선택. 기본값을 우리가 정하지 않는다. 둘 다 비워둔 상태로 출력해도 무방.

### [섹션 5] 서명란

```
                                    20  .   .   .
                                              (서명/인)
```

날짜는 자동 채움 가능하되, 서명란은 반드시 공란.

## 구현 시 주의

1. **PDF 생성은 `window.print()` + `@media print` CSS로 한다.**
   pdf-lib/jsPDF 한글 폰트 임베딩은 시간 낭비이며 CLAUDE.md에서 금지하고 있다.

2. **A4 한 장에 들어가는 것을 목표로 한다** — 서식 1은 짧아서 보통 한 장이다.
   다만 **한 장을 전제로 만들지는 않았다.** 큰 글씨(11pt)나 긴 입력에서는 두 장이 되고,
   화면이 미리 "현재 내용은 N페이지로 출력됩니다"라고 알린다.
   쪽 나눔은 `src/lib/paginate.js` 가 하고, 예고=실제를 `tests/run-print.sh` 가 검증한다.

3. 화면 표시용 컴포넌트와 인쇄용 레이아웃을 분리하지 말고,
   같은 DOM에 `@media print` 규칙만 다르게 준다. 두 벌 관리하면 어긋난다.

4. **서식은 2종이다.** 이 문서가 명세하는 「자동화평가 결과에 대한 설명요구서」는
   법 제1항(R1, R2)만 커버한다.

   제2항의 R3(유리한 정보 제출) / R4(정정·삭제) / R5(재산출)에 대응하는
   **「기초정보 정정·삭제 및 자동화평가 재산출 요청서」가 별도로 존재함이 확인됐다**
   (복수 저축은행이 두 서식을 함께 비치).

   → `/document` 화면은 문서 2종 생성으로 설계한다.
