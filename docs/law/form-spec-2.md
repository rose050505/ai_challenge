## [섹션 1] 제도 안내 — 고정 문구, 수정 금지

### 원문 (verbatim, 2026-08-23 확보 · **2026-08-30 원본 대조 완료**)

```
저축은행은 고객의 요청에 따라 자동화평가 결과, 자동화평가의 주요 기준 및 자동화평가에
이용된 기초정보의 개요를 설명하고 있으며, 기초정보가 정확하지 않은 경우 해당 정보에 대한
정정ㆍ삭제 및 수정된 정보를 활용하여 자동화평가 결과를 재산출하여 줄 것을 저축은행에
요청할 수 있습니다. 다만, 해당 기초정보가 당사가 직접 수집한 정보가 아니라 신용정보집중기관
또는 개인신용평가회사, 개인사업자신용평가회사 또는 기업신용조회회사로부터 수집한
타 금융회사의 정보인 경우에는 해당 금융회사에 정정ㆍ삭제를 요청하여야 합니다.
```

✅ **원본 대조 완료 (2026-08-30).** PDF를 레이아웃 보존 방식으로 재추출해 대조했다.
섹션 1과 섹션 2 리드는 추출본과 원문이 일치했다. 다른 다섯 군데는 아래 표대로 교정했다.

→ 상수: `FORM_CORRECTION_REQUEST.sections[0].verbatimText`
→ `verbatimVerified: true`. 화면의 "원본 대조 전" 경고는 제거했다.

> "신용거래능력판단정보" 붙여쓰기는 **서식에 인쇄되는 라벨에만** 적용한다.

> 서식 원문 재현과 우리 화면 용어는 별개다 → 상수 `BASE_INFO_CATEGORIES[capacity].formLabel`.

### ★★ 라우팅 규칙 (이 서비스의 핵심 분기)

> 다만 해당 기초정보가 **당사가 직접 수집한 정보가 아니라**
> 신용정보집중기관 또는 개인신용평가회사, 개인사업자신용평가회사 또는
> 기업신용조회회사로부터 수집한 **타 금융회사의 정보**인 경우에는
> **해당 금융회사에 정정·삭제를 요청**하여야 합니다.

→ 정정 대상 정보의 **출처에 따라 요청 상대방이 달라진다.**
→ 사용자는 이 판단을 스스로 할 수 없다. **여기가 서비스의 실질 가치다.**

`/diagnose` 분기 로직:
```
정정하려는 정보가
  ├─ 이 회사와의 거래에서 발생한 것        → 이 회사에 서식 2 제출
  ├─ 다른 금융회사와의 거래에서 발생한 것  → 그 금융회사에 서식 2 제출
  └─ 출처를 모름                          → 먼저 R2(기초정보의 개요 설명)로
                                            출처를 확인한 뒤 재판단
```

세 번째 분기가 중요하다. **서식 1(설명요구서)이 서식 2의 선행 단계가 되는 경우가 있다.**
서비스가 "먼저 이걸 내고, 답을 받은 뒤 저걸 내세요"라는 순서를 제시할 수 있어야 한다.

## [섹션 2] 정정·삭제 요구 (R4)

리드 문장 원문 (밑줄이 사용자 입력, verbatim):
```
______(신청자 성명)______ 은(는) 기초정보 정정ㆍ삭제 및 자동화평가 결과 재산출과 관련하여
귀 저축은행의 상기 설명을 읽고 이해하였으며, 저축은행이 보유하고 있는 본인의 기초정보 중
정확하지 않거나 최신의 정보가 아닌 내용이 있어 아래와 같이 정정 및 삭제를 요구합니다.
```

→ 상수: `sections[1].leadPlaceholder` + `sections[1].leadRest`
   (화면에서 문자열을 잘라 쓰지 않도록 자리표시자 앞뒤를 미리 나눠 둔다)

표 구조 — 3열:

| 구 분 | 현행 정보 | 정정 또는 삭제 내용 |
|---|---|---|

"구 분" 행은 **5종 고정**:

| ID | 라벨 | 비고 |
|---|---|---|
| `identity` | 식별정보 | |
| `transaction` | 거래내용 판단정보 | |
| `creditworthiness` | 신용도 판단정보 | |
| `capacity` | 신용거래능력 판단정보 | 서식 인쇄 라벨은 **신용거래능력판단정보**(붙여쓰기) — `formLabel` |
| `other` | 기타 정보 | |

> 이 5분류는 시행령 §31-2⑧2호가 언급하는
> "신용거래 판단정보, 신용도 판단정보, 신용거래능력 판단정보 등"과 대응한다.
> R2(주요 기준 설명)에서 받게 될 답변의 분류 체계와 같으므로,
> 서비스에서 두 화면의 분류를 일치시키면 사용자가 흐름을 이해하기 쉽다.

각 행은 선택적. 해당 없는 분류는 비워둔다.

## [섹션 3] 유리한 정보 제출 (R3) — ★ /strategy의 출력 지점

헤더:
```
다음과 같이 자동화평가 결과의 산출에 유리하다고 판단되는 정보를 제출합니다.
(해당 사항이 없는 경우 본란 삭제)
```

표 구조 — 2열:

| 정보명 | 세부 내용 |
|---|---|

서식에 실린 예시 행:
```
건강보험 납부실적 | ’xx년 x월 x일∼’◊◊년 ◊월 ◊일까지 연체없이 납부
```

> 문장부호는 원문 그대로다. 작은따옴표는 `’`(U+2019), 물결은 `∼`(U+223C)이고
> 앞뒤 공백이 없다. ASCII 의 `'` 나 `~` 로 바꾸지 말 것. "연체없이"는 붙여 쓴다.
> 상수는 `R3_SCOPE.formExample` 한 곳뿐이고, 서식은 그것을 참조한다.

> ★ 이 예시가 R3의 성격을 규정한다.
> **금융거래 이력이 아닌 비금융 정보로 신용을 보강하는 것.**
> 즉 금융이력 부족자(씬파일러)를 정확히 겨냥한 조항이다.
> `/strategy`의 LLM 프롬프트는 이 예시의 결을 따라야 한다.
> "정보명 / 세부 내용(기간·실적을 구체적 수치로)" 형식으로 출력하게 설계할 것.

`/strategy` → 섹션 3 자동 채움이 이 서비스의 핵심 산출 경로다.

## [섹션 4] 재산출 요구 (R5)

고정 문구:
```
상기 오류정보를 정정 또는 삭제하고, 수정된 정보를 활용하여
본인에 대한 개인신용평가 결과를 재산출하여 줄 것을 요구합니다.
```

사용자 입력 없음. 체크 여부만 결정.

> 섹션 4는 섹션 2에 의존한다. 정정할 내용이 없으면 재산출 요구도 성립하지 않는다.
> UI에서 섹션 2가 비어 있으면 섹션 4를 선택할 수 없게 한다.

## [붙임] 및 서명

```
※ 붙 임 : 증빙자료

                                    20  .   .   .
                                            (서명 / 인)
```

> "붙 임" 과 "(서명 / 인)" 의 공백은 원문 그대로다.
> 서명 표기는 **서식 2 전용**이다(`FORM_CORRECTION_REQUEST.signature.signatureMark`).
> 서식 1은 원본 대조를 하지 않았으므로 공용 `FORM_SIGNATURE_TEXTS.signatureMark` 를 유지한다.

증빙자료는 파일 첨부가 아니라 **"무엇을 함께 내야 하는지 안내"**로 처리한다.
법 §36-2②2 전제가 "정확하지 아니하거나 최신이 아니라고 판단되는 경우"이므로,
그 판단의 근거 자료를 붙이는 것이 실효성을 높인다.

## ★ 기관명 치환 규칙 (2026-08-23 확정)

원문이 저축은행 공개본이므로 "저축은행"이 그대로 박혀 있다.
은행·카드사 이용자에게 어색하므로 **기관명만** 업권에 맞게 치환한다.

### 치환 대상

**"저축은행" 문자열뿐이다. 총 4곳.**

| 위치 | 원문 | 치환 후 |
|---|---|---|
| 섹션 1 첫 문장 | `저축은행은 고객의 요청에 따라` | `{기관}은/는 고객의 요청에 따라` |
| 섹션 1 첫 문장 끝 | `저축은행에 요청할 수 있습니다` | `{기관}에 요청할 수 있습니다` |
| 섹션 2 리드 | `귀 저축은행의 상기 설명` | `귀 {기관}의 상기 설명` |
| 섹션 2 리드 | `저축은행이 보유하고 있는` | `{기관}이/가 보유하고 있는` |

### ★ 명시적 예외 — 조사(은/는, 이/가) 보정 (기능명세서 기재 항목)

원문의 "저축은행**은**", "저축은행**이**"는 받침이 있는 이름을 전제한다.
받침 없는 업권명("카드사", "증권사", "보험회사", "금융회사")을 그대로 넣으면
**"카드사은", "카드사이"** 가 되어 문서가 깨진다.

→ 치환된 **기관명 바로 뒤의 조사 한 글자만** 받침에 맞게 고친다.
   `substitution.adjustParticles: true` (기본값)

| 업권 | 결과 |
|---|---|
| 은행 / 저축은행 / 신협 | 은행**은** … 은행**이** 보유 (원문 그대로) |
| 카드사 / 증권사 / 보험회사 / 금융회사 | 카드사**는** … 카드사**가** 보유 |

#### 결정 (2026-08-23) — 보정한다

**"verbatim, 한 글자도 바꾸지 않는다"는 고시 안내문 자체에 적용되는 규칙이고,
조사는 치환된 명사에 문법적으로 결합하는 부분이므로 치환의 일부다.**

"카드사은"을 인쇄해 금융회사에 제출하는 것이 원문 훼손보다 나쁘다.

| | |
|---|---|
| 적용 범위 | 치환된 기관명 **바로 뒤 한 글자**의 조사뿐 |
| 건드리지 않는 것 | 그 외 모든 문구, "당사", 조사가 아닌 글자(에/의 등 형태 불변 조사 포함) |
| 의미 변화 | 없음 |
| 끄는 법 | `substitution.adjustParticles: false` |
| 구현 | `src/lib/neutralize.js` (한글 받침 판별 후 짝 치환) |

> 이 예외는 **기능명세서에 기재한다.** 숨기지 않는다.

### 절대 치환하지 않는 것

**"당사"는 치환하지 않는다.** 서식 발행 주체를 가리키는 표현이다.
나머지 문구도 일절 수정하지 않는다.

### 치환값 — 업권별 shortLabel

라벨 전체가 아니라 문장에 넣을 짧은 업권명을 쓴다.
(`INSTITUTION_SECTORS[].shortLabel`)

| 업권 | shortLabel |
|---|---|
| 은행 | 은행 |
| 금융투자업자 · 증권금융회사 · 종합금융회사 · 명의개서대행회사 | 증권사 |
| 보험회사 | 보험회사 |
| 상호저축은행 | 저축은행 |
| 신용협동조합 | 신협 |
| 여신전문금융회사 · 겸영여신업자 | 카드사 |
| 농협은행 · 수협은행 | 은행 |
