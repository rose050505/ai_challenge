## 새로 발견한 문제와 조치

### ★ 서식 2에서 방금 적은 값이 인쇄물에서 빠졌다 (Phase 0)

가장 무거운 것. 어제 고친 "잘림"과 **다른 결함**이고, PDF 에서 글자를 뽑아 세는 시험을
새로 만들면서 드러났다.

`PagedSheet` 가 쪽 나눔 결과를 **블록 덩어리째** 상태에 담고 있었다. 칸에 글자를 넣으면
React 요소는 새로 만들어지는데, 쪽 나눔이 그대로면 중복 방지 검사에 걸려 상태를 갱신하지
않는다. 그러면 화면과 **인쇄물이 예전 요소를 계속 그린다.** 즉 **마지막에 적은 값이
종이에서 빠진다.** 다른 칸을 한 번 더 건드리면 그제야 나타난다.

→ 쪽 나눔은 **id 만** 기억하고, 그릴 때 지금의 블록에서 찾도록 바꿨다. 어긋날 수가 없다.

함께: 표의 행 하나가 한 쪽보다 크면 쪼갤 수 없어 실제 쪽 수가 예고보다 많아진다.
숨기지 않고 화면에 "실제로는 이보다 더 나올 수 있습니다"라고 적는다.

**검증**: `tests/tprintlong.mjs` 신설 — 서식 2종 × 글자 크기 2종 × 긴 값 5종 = 20조합에서
빈 상태와 채운 상태를 각각 인쇄해 **늘어난 글자 수 = 넣은 글자 수**를 확인한다. 42/42.

### 접근성 (Phase 4)

- `aria-controls` 가 **없는 id 를 가리키고 있었다** — 6화면 전부. 접힌 패널을 DOM 에서 빼는
  구조인데 속성은 남아 있었다. 패널이 실제로 있을 때만 준다.
- 인쇄 서식 표의 `th` 에 `scope` 가 없었다. 세로 머리 `row`, 위 머리 `col`.
  **보이는 모양과 인쇄물은 그대로다.**

## 판단해서 하지 않은 것

| 무엇 | 왜 |
|---|---|
| **라우트 코드 스플리팅** | 이득 gzip 8~10KB(느린 3G 0.2초). 대가로 인쇄 흐름과 둘러보기가 청크 로딩을 사이에 둔다. 심사 중 화면이 잠깐 비는 쪽이 훨씬 나쁘다 |
| **AI 응답 스트리밍** | 서버 가드(`applyGuards`)는 **완성된 JSON 이 있어야** 돈다. 토큰을 그대로 흘리면 지어낸 인용이 걸러지기 전에 화면에 뜬다. 체감을 위해 신뢰를 내주는 거래다 |
| **모달 배경에 `inert`** | `aria-modal="true"` 로 이미 격리된다. 잘못 걸면 닫은 뒤 화면 전체가 잠긴다 |
| **서식 칸 길이 제한** | 이제 잘리지 않는다. 새 상한을 걸면 **이미 저장된 기록에서 값이 사라진다** |
| **두 탭 동기화** | 각 탭이 자기 것을 잃지는 않는다. 동결 직전에 저장 경로 수술은 위험하다 |
| **서비스워커(오프라인)** | 캐시가 낡은 판을 붙잡는 사고가 오프라인 새로고침 불가보다 훨씬 나쁘다 |
| **랜딩 h1 문구** | "대출이 거절됐을 때"가 금리 인상 사용자에겐 남 얘기로 읽힐 수 있다. 다만 자가진단이 회수하고, h1 은 서비스 정체성이라 밤중에 혼자 바꿀 자리가 아니다 |

1. **랜딩 h1** — 위 표의 마지막 줄. 바꿀지 말지.

   보인다. 지금 배치는 **심사위원(회신문 없음) 우선**이다. 실사용자 우선으로 바꾸려면
   붙여넣기 칸을 위로 올려야 하는데, 그러면 심사 체험이 나빠진다. 어느 쪽을 택할지.

   버튼이 나온다. 위로 올리면 읽기 전에 나가고, 두면 멀다.
4. **서식 1 정본 대조** — 별지 15의2 HWP 를 못 구했다. 8/30 개정본(고시 제2026-37호)이
